# Coda

The change we followed through these pages has been merged, shipped, watched, and measured. Whatever it taught is already written down: as a leaderboard entry, a story, or the next issue in the tracker. The loop does not terminate, and that is not a flaw. It is the design.

If you keep only four things from this handbook, keep the throughlines. Decide on evidence, not intuition. Capture the trail, because the decision will outlive your memory of it. Keep the core reusable and the task layer disposable. And when you settle a standard, make it executable, so the machine holds the line while you think about the next change.

The tools in these pages will age; some already have. The loop is what stays. Take the next issue, and [begin again](lifecycle.md).
